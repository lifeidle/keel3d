# 剩余工作评估（目标达成度）

> 目标回顾：**选形式 → 配基底 → 像搭积木一样做出各种游戏**；功能丰富但**按需付费**。

## 1. 已经具备的

| 层 | 内容 | 状态 |
|---|---|---|
| 地基 L1 | WebGPU 循环、物理、输入、质量、资产 | 完成 |
| 几何积木 L2 | Pool / Path / Steering / A* / Camera / Chunk / Map / Terrain | 完成 |
| 启动 DX V2 | registry、defineGame、宿主、`new-game` | 完成 |
| 选型页 | `hub.html` 形式 → 基底说明 | 完成 |
| 样例 | FPS / 塔防 / 修仙 / 飞行 / 赛车 / 模板 | 完成（玩法深度不一） |

## 2. 还差什么（才能「搭积木出游戏」）

**不是每个游戏都要重配一整套引擎**——差的是**玩法标准件**和**拼装文档**。

| 缺口 | 不做的后果 | 工作量 |
|---|---|---|
| 玩法积木（血量/波次/经济/网格放置/计分） | 每个游戏手写，重复劳动 | **2–3 天** |
| UI 积木（面板/Toast/结束叠层） | HUD 各写各的 | **0.5–1 天** |
| 数据驱动生成（单位表 + Spawner） | 敌人/建筑样板代码 | **0.5–1 天** |
| 配方（TD / 生存一键骨架） | 「最快路径」不成立 | **0.5–1 天** |
| 积木手册 + hub 链到文档 | 别人不知道怎么拼 | **0.5 天** |
| （可选）夜袭音频瘦身 / npm 发包 | 体积与分发 | 不挡本目标 |

**合计还要约 4–6 个工作日**做到「勾选积木就能出可玩原型」。

## 3. 不同游戏要不要配很多内容？

| 你要配的 | 量 | 说明 |
|---|---|---|
| 模型 / 颜色 / 音效 | 按题材 | 美术，框架给不了 |
| 数值表（血量、价格、波次） | 一张表 | 配置，不是代码 |
| 专属 System | 通常 **0–3 个** | 只有差异化玩法才写 |
| 地图 / 相机 | 一行 spec | 积木已覆盖 |

**结论**：有了玩法积木后，新游戏 ≈ **数据 + 少量专属逻辑**；不需要为每个品类重新搭引擎。
